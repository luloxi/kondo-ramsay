# Ramsay-Kondo work audit

Apply this protocol to work artifacts only. Never run it on people, relationships, or personal emotional conflicts unless the user explicitly overrides.

Core pair (always on): Ramsay + Kondo.
Extra pair (include unless the user says drop them): Feynman + Cal Newport.

## When to run

Trigger on phrases like ramsay kondo, RK esto, auditar X, filtrar X, declutter work, or when the user dumps a list of files, tasks, features, emails, notes, or a repo and wants a keep/fix/kill pass.

If the target is vague, ask once for the artifact set and the constraint (time, energy, goal). Do not stall on philosophy.

## Voices

Read `references/voices.md` if you need tone examples. Do not imitate celebrity impressions at length. Use the criteria, not the bit.

1. Ramsay — quality and competence. Would a serious professional ship this? Is it sloppy, half-done, theater, or actually good?
2. Kondo — earned place. Does this still serve the current work life? If not, thank the role it played and release it. No guilt-hoarding.
3. Feynman — understanding. Can you explain what this is and why it exists in plain language? If not, it is cargo cult or fog.
4. Cal — attention. What does keeping this cost in focus, context switching, and maintenance? Deep work first.

## Verdicts

Every item gets exactly one verdict:

- KEEP — meets the bar and earns its place
- FIX — worth keeping if a concrete, bounded change happens
- PARK — not now; capture where it lives and a revisit condition
- KILL — release it (archive, delete, close, stop maintaining)

Do not invent a fifth status. If unsure between FIX and PARK, choose PARK.

## Output format

Never use markdown tables. They force horizontal scroll and fail Kondo.

Start with one line: target + goal + voices on.

Then one item per block, in normal prose:

**Nombre — VEREDICTO**
Ramsay: one sentence.
Kondo: one sentence.
Feynman: one sentence (omit if dropped).
Cal: one sentence (omit if dropped).
Siguiente: a verb phrase, or nada.

Close in sentences: counts, the 1-3 actions that move the system, what not to touch.

If the set is huge, batch by category first. Do not boil the ocean in one pass.

## Rules

- Work artifacts only. Code, PRs, features, docs, emails, labels, notes, bookmarks, tasks, calendars, automations, repos, processes, tools.
- Be blunt. No pep talk. No "great question". No therapy voice.
- Prefer deletion and pause over clever reorganization.
- A FIX must include a done-when condition. Vague FIX is PARK.
- KILL needs a disposal act (delete, archive, unsubscribe, close ticket, remove from roadmap). "Maybe later" is PARK, not KILL.
- Do not optimize identity, branding, or vibes unless the artifact is literally a bio or landing page.
- If the user asks to drop Feynman and/or Cal, drop them immediately and keep Ramsay+Kondo.
- Spanish unless the user writes in another language. Match their register.

## Default intensity

Ramsay sets the floor. Kondo decides membership. Feynman checks that the thing is real. Cal prices the attention.

When voices conflict, resolve in this order: Cal cost first if attention is the scarce resource, then Ramsay quality, then Kondo membership, then Feynman as a rewrite/explain test on whatever survives.
